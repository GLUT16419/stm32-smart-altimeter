# 气压高度解算与卡尔曼滤波 —— 答辩文档

> 适用场景：嵌入式系统课程实习答辩。
> 本文档把「气压→高度」的推导、卡尔曼滤波的推导、以及「为什么这样设计」串成一条线，
> 并给出可直接照读的演讲结构与可能被追问的问题。所有公式都对应到 `Core/Src/` 下的真实代码。

## 一、问题引入与系统设计总览（先讲这张图）

**要解决的问题**：气压传感器只能测「气压」，而人需要的是「高度」和「爬升/下降速度」。
气压和高度之间不是线性关系，而且气压噪声会被放大成高度抖动，所以不能直接拿来用。

**系统数据流（先给评委一个全局视角）**：

```
气压传感器原始值 P_raw
   │
   ├─ 自适应标量卡尔曼滤波  ──►  去噪气压 P_filt
   │
   └─ 双传感器融合(MS5611×0.5 + BMP280×0.5) ──► P_fused
            │
            ▼
   气压方程 PressureToAltitude(P_fused, P0)  ──►  高度 h
            │  （或）
            ▼
   扩展卡尔曼 EKF_Update(P_raw, dt)  ──►  高度 h + 垂直速度 v
```

- `P0`（参考海平面气压）由预设锚点反算（上电就地归零）。
- 气压方程负责「P→h 的几何映射」。
- 卡尔曼负责「在噪声和动态响应之间找最优平衡」。

**一句话总结设计哲学**：气压方程是物理基础（离线推导、确定性的）；卡尔曼是统计工具（在线、自适应），两者分工明确。

## 二、气压 → 高度公式推导

### 2.1 两个物理定律（一切的起点，必须讲清楚）

**(1) 流体静力学平衡**：高度升高 `dh`，气压下降量等于这薄层空气的重力：

\[
\frac{dp}{dh} = -\rho\, g
\]

**(2) 理想气体状态方程**（干空气比气体常数 \(R = 287.05\ \text{J/(kg·K)}\)）：

\[
\rho = \frac{p}{R\,T}
\]

把密度 \(\rho\) 代入，消去变量，得到「气压—高度」的核心微分方程：

\[
\frac{dp}{p} = -\frac{g}{R\,T}\, dh
\]

> 讲解话术：这个方程告诉我们，气压随高度的变化率取决于「温度 T」。
> 后面两种不同的算法，本质区别只有一个——**对温度 T 做了什么假设**。

### 2.2 模型 A：等温模型（温度恒定的解析解）

**假设**：温度 \(T\) 是常数（不随高度变化）。直接对微分方程两边积分：

\[
\int_{p_0}^{p}\frac{dp}{p} = -\frac{g}{R T}\int_0^{h} dh
\quad\Rightarrow\quad
\ln\frac{p}{p_0} = -\frac{g\,h}{R\,T}
\]

反解出高度，得到漂亮的**解析反函数**：

\[
\boxed{h = -\frac{R\,T}{g}\,\ln\!\left(\frac{p}{p_0}\right)}
\]

这正是你 `Core/Src/altitude_convert.c` 里的实现（标准温度版，第 17 行）：

```17:17:Core/Src/altitude_convert.c
    float altitude = -(287.05f * 288.15f / 9.80665f) * logf(ratio);
```

带实时温度补偿的版本只把常数 \(T\) 换成 `temperature_c + 273.15`（第 46–51 行），
而 EKF 在气压域做量测时用的也是这条公式（`altitude_ekf.c` 第 98 行）：

```98:98:Core/Src/altitude_ekf.c
    return -(GAS_CONSTANT * SEA_LEVEL_TEMP / GRAVITY) * logf(ratio);
```

### 2.3 模型 B：ISA 国际标准大气（更贴近真实大气）

**假设**：对流层（0~11 km）温度随高度**线性递减**，
\(T(h) = T_0 - L h\)，其中 \(T_0=288.15\ \text{K}\)，递减率 \(L=0.0065\ \text{K/m}\)。

代回微分方程并积分，得到气压随高度的**正算**公式：

\[
\frac{p}{p_0} = \left(1 - \frac{L\,h}{T_0}\right)^{\frac{g}{R L}}
\]

再反解高度：

\[
\boxed{h = \frac{T_0}{L}\left[1 - \left(\frac{p}{p_0}\right)^{\frac{R L}{g}}\right]}
\]

对应 `altitude_convert.c` 第 14 行（`#if ALTITUDE_FORMULA_ISA` 分支）：

```14:14:Core/Src/altitude_convert.c
    float altitude = (ISA_T0 / ISA_L) * (1.0f - powf(ratio, ISA_L * ISA_R / ISA_G));
```

### 2.4 两种模型对比与选型（评委常问「为什么不用 ISA 更准的？」）

| 维度 | 等温模型 | ISA 标准大气 |
|------|----------|--------------|
| 温度假设 | 常数 | 线性递减（考虑越高越冷） |
| 精度 | 温度接近标准值时够用 | 更贴近真实大气 |
| 反函数 | 有解析反函数（对数），数值稳定 | 有解析反函数（幂），但 EKF 雅可比更复杂 |
| 你的代码 | EKF、温度补偿版选用 | 主 `altitude_convert` 默认分支 |

**设计理由**：
- 实际工程在几百米范围内，温度随高度的变化很小，等温近似误差可接受；
- 等温形式有**简单、稳定的解析反函数**，而且它的量测雅可比是指数形式、计算量小、数值稳定——这对 MCU 上的 EKF 非常友好；
- 所以 EKF 和实时温度补偿版都选等温；而 `altitude_convert.c` 默认保留 ISA 分支，作为更精确的备选对照。

### 2.5 反算参考气压 P0（标定 / 预设锚点）

已知「真实高度 \(h\) + 此刻实测气压 \(p\)」，反过来求参考海平面气压 \(P_0\)，就是上面公式的逆向：

- 等温：\(P_0 = p\cdot e^{\,g h/(R T)}\)
- ISA：\(P_0 = p \big/ \left(1-\frac{L h}{T_0}\right)^{g/(R L)}\)

这就是你 `main.c` 里 `ApplyAltPreset` 做的事（锚定 160.730 m / ID1122）。
**含义**：上电时拿此刻气压，按公式反推出 \(P_0\)，之后所有高度都以这个 \(P_0\) 为基准——
所以预设一个锚点，设备就「就地归零」到 160.730 m，无需去海边标定。

## 三、为什么必须滤波（用数量级说服评委）

对高度关于气压求导，看 1 Pa 气压误差会变成多少米高度误差：

\[
\frac{dh}{dp} = -\frac{R T}{g\,p}
\approx -\frac{287\times 288.15}{9.80665\times 101325}
\approx -0.084\ \text{m/Pa}
\]

**结论**：地面附近约 **12 Pa 的噪声就对应 1 m 的高度抖动**。
传感器本身（MS5611 std≈3 Pa、BMP280≈0.35 Pa）看着很小，
但温漂、气流、微型风机扰动会把这些放大几倍到几十倍。
直接把气压转高度会乱跳，所以**滤波是必需的**，不是锦上添花。

## 四、卡尔曼滤波：推导与理解

### 4.1 状态空间建模（先定义问题）

`Core/Src/kalman_filter.c` 是一个**一维标量**滤波器。它隐含的模型是：

\[
\begin{aligned}
x_k &= x_{k-1} + w_k, \quad &w_k\sim\mathcal N(0,Q) \quad\text{（过程噪声：认为真值近似不变）}\\
z_k &= x_k + v_k, \quad &v_k\sim\mathcal N(0,R) \quad\text{（量测噪声：传感器读数）}
\end{aligned}
\]

> 直觉：真高度在短时间内几乎不变，气压读数只是被噪声污染了。
> 卡尔曼在这里退化成一个**最优加权平均 / 低通滤波器**。

### 4.2 标量 KF 五步推导（核心，必须会推）

记上一时刻估计为 \(\hat x_{k-1}\)，估计误差方差 \(P_{k-1}\)。

**(1) 预测**：状态转移 \(F=1\)，预测值等于旧估计，协方差叠加过程噪声：

\[
\hat x^- = \hat x_{k-1}, \qquad P^- = P_{k-1} + Q
\]

**(2) 计算卡尔曼增益**：在「使新估计方差最小」意义下最优，结果为：

\[
K = \frac{P^-}{P^- + R}
\]

**(3) 量测更新（融合）**：用预测值和测量值按增益加权：

\[
\hat x_k = \hat x^- + K\,(z_k - \hat x^-)
\]

**(4) 更新协方差**：

\[
P_k = (1-K)\,P^-
\]

这正好就是你 `KalmanFilter_Update` 的四行（`kalman_filter.c` 第 17–28 行）：

```17:28:Core/Src/kalman_filter.c
float KalmanFilter_Update(KalmanFilter_TypeDef *kf, float z)
{
    kf->p = kf->p + kf->q;
    kf->k = kf->p / (kf->p + kf->r);
    kf->x = kf->x + kf->k * (z - kf->x);
    kf->p = (1 - kf->k) * kf->p;
    return kf->x;
}
```

### 4.3 怎么「理解」卡尔曼增益 K（讲直觉，评委最爱听）

看 \(K = P^-/(P^-+R)\) 的分子分母：

- 我对旧估计**很自信**（\(P^-\) 小）→ \(K\) 小 → 更相信旧值、输出更平滑；
- 传感器**很吵**（\(R\) 大）→ \(K\) 小 → 不信新测量。

它是**自动、最优**地权衡「信模型」还是「信传感器」，而不是人工拍一个固定权重。

### 4.4 稳态等价于指数滑动平均（EMA）

迭代到稳态后 \(P\)、\(K\) 都收敛成常数，此时：

\[
\hat x_k = (1-K)\hat x_{k-1} + K\,z_k
\]

**这就是 EMA**，和你 `main.c` 里 `PRESSURE_EMA_ALPHA` 那套是同一类东西。
区别在于：EMA 的 \(\alpha\) 是人工拍的，卡尔曼的 \(K\) 是数学推导出来的最优解。

### 4.5 自适应 KF（你的 `KalmanFilter_Update_Adaptive`）

**设计动机**：静止时残差小，要多平滑（\(K\) 小）；运动时残差大，要快速跟踪（\(K\) 大）。
固定 \(Q\) 做不到两者兼顾，所以**动态调 \(Q\)**：

- 残差 std 大 → 把 \(Q\) 乘大（`KF_Q_INCREASE`）→ \(P^-\) 变大 → \(K\) 变大 → 跟得快；
- 残差小 → \(Q\) 衰减回基础值 → 平滑。

```78:84:Core/Src/kalman_filter.c
    kf->p = kf->p + kf->q;
    kf->k = kf->p / (kf->p + kf->r);
    kf->x = kf->x + kf->k * residual;
    kf->p = (1 - kf->k) * kf->p;
```

BMP280 专用版只是换了一套更小的阈值、更快的 \(Q\) 变化率——因为它本底噪声小，需要更灵敏才能追得上运动。

### 4.6 扩展卡尔曼 EKF（你的 `altitude_ekf.c`）—— 高一级的玩法

普通 KF 只在「高度」这个标量上滤波；EKF 同时估计 **高度 \(h\) 和垂直速度 \(v\)** 两个状态，
并且量测是在**气压域**比较残差（而不是先把气压转成高度再比），
这避开了对数反函数的非线性问题。

**(a) 预测用运动学模型**（匀速 + 白噪声加速度）：

```47:48:Core/Src/altitude_ekf.c
    float predicted_height = ekf->height_m + ekf->velocity_mps * dt_s;
    float predicted_velocity = ekf->velocity_mps;
```

协方差预测里把 `accel_var`（加速度方差）按 \(dt^2,dt^3,dt^4\) 项融进去（第 51–54 行），
这就是标准「恒定速度 + 随机加速度扰动」模型。

**(b) 非线性量测用雅可比线性化**：
观测函数 \(f(h)=P_0 e^{-g h/(RT)}\)，对 \(h\) 求导得雅可比 \(H\)：

```15:19:Core/Src/altitude_ekf.c
static float AltitudeEKF_PressureJacobian(float height_m, float reference_pressure_pa)
{
    float exponent = -(GRAVITY * height_m) / (GAS_CONSTANT * SEA_LEVEL_TEMP);
    return reference_pressure_pa * expf(exponent) * (-GRAVITY / (GAS_CONSTANT * SEA_LEVEL_TEMP));
}
```

然后用这个 \(H\) 算残差 \(z - f(\hat h)\)、增益和协方差更新（Joseph 形式，第 64–86 行）。

**EKF 相比标量 KF 的优势**：
因为状态里多了**速度通道**，EKF 能靠运动学约束把气压的瞬时突变「滤平」，
同时还能**直接输出垂直速度**（爬升/下降率）——这是纯高度 KF 给不了的。

## 五、设计理由总结（答辩收尾时念这段）

1. **分两层解耦**：气压方程（物理、离线、确定）负责 P→h 映射；卡尔曼（统计、在线、自适应）负责去噪。
   分工清晰，任一层可独立替换或调试。
2. **等温模型为主、ISA 备选**：等温有稳定解析反函数、EKF 雅可比简单，适合 MCU 实时运算；
   ISA 作为更精确对照保留。
3. **锚点反算 P0**：无需去海边标定，上电就地归零，工程实用性强。
4. **自适应 + EKF 双保险**：自适应标量 KF 在气压域快速去噪；EKF 利用速度动力学约束进一步平滑并输出垂直速度。
5. **误差数量级驱动设计**：12 Pa≈1 m 的放大效应，是从数学上证明「滤波不是可选项」的依据。

## 七、可能被追问的问题与回答（Q&A 准备）

**Q1：为什么不直接用 GPS 测高度？**
A：GPS 垂直精度差（几米到十几米）、更新慢、室内/遮挡失效；气压计便宜、高频、室内可用，二者互补。

**Q2：为什么不用一阶低通滤波，非要卡尔曼？**
A：低通要人工拍截止频率，且无法区分「传感器噪声」和「真实运动」。卡尔曼用方差自动权衡，运动时不拖尾、静止时更平滑，还能给出估计的不确定性。

**Q3：EKF 里的雅可比为什么在气压域算，而不是高度域？**
A：量测本身是非线性气压函数 p=f(h)。在气压域比较残差，雅可比是指数形式、简单稳定；若先在高度域比较，会引入对数反函数，数值更敏感。

**Q4：P0 会漂移吗？怎么处理？**
A：会，天气变化会改变海平面气压。我的方案是提供预设锚点随时重新标定；若需长期稳定，可后续加入温度补偿或定期用 GPS/已知高度点刷新 P0。

**Q5：Q 和 R 怎么取的？**
A：Q 来自对「真值变化剧烈程度」的先验（过程噪声），R 来自传感器数据手册的噪声指标；自适应版本还会根据残差实时调整 Q，所以不需要非常精确的初值也能工作。

**Q6：等温模型误差有多大？**
A：在几百米范围、温度接近 15°C 时，等温与 ISA 差在亚米级，远小于传感器噪声，因此等温近似完全够用；且已保留 ISA 分支作为更精确备选。
